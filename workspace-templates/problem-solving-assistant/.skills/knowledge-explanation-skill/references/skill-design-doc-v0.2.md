# 知识点分层讲解 Skill 研发思路

更新时间：2026-06-05

## 1. 背景定位

本 Skill 对应项目中第 5 个智能体场景：学伴线 / 学生 / 知识点或题目讲解。

核心问题不是"生成一段更详细的讲解"，而是解决讲解千人一面：基础薄弱学生听不懂，能力较强学生嫌慢，教师也难以快速判断先补哪个前置知识、选哪道典型例题、提醒哪些易错点。

因此本 Skill 应定义为一个弹性闭环型讲解编排技能：

```text
知识点定位 -> 知识类型判断 -> 前置知识检查
-> 选择一个教学动作 -> 直觉/规则/例子/回应
-> 学生反馈 -> 错因修正或继续推进
-> 根据结果回流到对应讲解层级
```

注意：这是跨多轮闭环，不是单轮输出清单，也不是每轮都要按顺序走完的固定工作流。学生只抛出知识点时，首轮应先判断知识类型，再先模糊后具体，只给直觉抓手、关键属性或一个微检查。主提示语要尽量简单，用“知识类型 + 单教学动作”控制输出。

## 2. 首批研发目标

首批不追求完整专家系统，不依赖长期学生画像，只基于本次输入、本次作答和显式年级信息完成可验收闭环。

MVP 需要跑通 9 个核心能力：

1. 知识点定位：将口语化知识点、教材位置或题目保守定位到本轮主知识点或题目卡点。
2. 知识类型判断：区分概念、规则/原理、解题步骤、具体例题、错误过程和总结/备课。
3. 前置知识检查：识别学生是否缺少必要前置知识。
4. 三层讲解：入门、标准、拓展三层输出风格和内容结构不同。
5. **语言风格与讲解策略**：根据层级和年级段选择风格档位和策略组合，控制"怎么讲"。
6. 教学动作选择：在目标澄清、前置确认、直觉入口、规则具体化、正例/反例、例题带做、错因修正、快速总结中选一种。
7. 经典例题：按学生反馈绑定典型例题、分步演示和方法总结。
8. 易错提醒：输出具体错误表现、原因和修正方式。
9. 即时检验与回流：根据检验结果决定继续补前置、重讲、练习或升级。

## 3. 数据依赖

当前阶段默认没有可用知识库、题库、教材库、课标库、错因库或学生画像。本 Skill 先按“无知识库 prompt-driven 原型”运行，内容依据主要是用户输入、对话上下文和 AI 通用学科知识。

## 5. 调用流程

### 5.1 知识点定位

输入可以是：

- 标准知识点名称，如"一元一次方程"。
- 口语化说法，如"移项怎么老错"。
- 教材位置，如"七年级上册第三章"。
- 题目文本或 OCR 结果。

当前无知识库模式下，Skill 不查真实图谱，也不输出标准知识点 ID、教材位置或课标边界。它只根据用户原话和 AI 通用学科知识保守定位主知识点；如果知识点歧义明显，只问一个澄清问题。

未来若接入真实图谱，可再使用 `knowledge-graph.json` 的 `alias` 字段做标准知识点映射。

### 5.2 前置知识检查

如果学生水平未知，优先用一个通用短问题确认最小前置。
如果输入中已有学生作答，则根据学生原话、题目步骤和 AI 通用学科知识保守推断前置薄弱点。

### 5.3 知识类型判断

前置检查前后都要判断本轮讲解对象属于哪类知识：

- 概念：给关键属性、正例/反例和小判断。
- 规则/原理：给直觉入口、准确规则和边界例子。
- 解题步骤：用 worked example 带当前关键一步。
- 具体例题：优先讲题里卡住的一步。
- 错误过程：定位第一处关键错误，再修这一小步。
- 总结/备课：给核心规则、边界、课堂追问或后续检查。

知识类型判断优先于风格选择。风格只改变表达口气，不改变教学动作和数学边界。

### 5.4 层级判定

层级包括：

- 入门层（entry）：先补前置知识和直观类比。
- 标准层（standard）：讲通用定义、典型微例和规范步骤。
- 拓展层（advanced）：讲变式、迁移、多解法和易混比较。

### 5.5 风格与策略选择

层级判定完成后，根据 `teaching-style-guide.md` 的规则选择：

1. **语言风格档位**：默认以安全版暴躁老哥风格为基线，口语短句、吐槽题目/符号/易错点；再按学生状态、教师场景和用户指定风格做覆盖。
2. **讲解策略组合**：从六种核心策略中按层级规则选取。
3. **年级段微调**：根据年级段适配矩阵做风格偏移。
4. **动态覆盖**：学生状态信号（连续错题、主动反馈等）可实时调整风格和策略。
5. **幽默尺度控制**：用生活化比喻、俏皮避坑、口诀感总结或安全吐槽增强记忆；禁止无关段子、嘲讽学生、网络梗和牺牲准确性的玩笑。

风格和策略选择可以在内部形成简短判断，便于追溯和评测；学生向输出默认不暴露内部字段。

```json
{
  "style": {
    "register": "safe_aggressive_bro",
    "strategies": ["analogy", "scaffold", "worked_example"],
    "humorUse": "吐槽负号和移项坑，但不攻击学生",
    "reason": "默认安全版暴躁老哥风格；entry层 + 七年级 → 保留轻量吐槽并降低密度；前置检查发现等式性质薄弱 → 加入analogy引入天平类比"
  }
}
```

### 5.6 讲解与例题

讲解不应只输出概念说明。概念类知识至少要有关键属性或正例/反例；规则类知识至少要有边界或微例；步骤类知识要绑定 worked example 的关键一步。
讲解内容由用户材料和 AI 通用学科知识生成，并按 `teaching-style-guide.md` 的风格和策略规则重新组织语言。
没有真实题库时，可以生成临时样题；学生向输出不暴露内部字段，但不能说成教材原题、真题或题库高频题。

### 5.7 即时检验与回流

每次讲解后只留一个检查点。当前无知识库模式下，检查点由 AI 根据当前讲解动作临时生成。
根据结果路由：

- 前置错：如果学生回应显示最小前置没掌握，回到前置知识补讲。
- 概念错：回到入门层，**降低密度，使用轻量暴躁老哥口吻或暖心家教型，并补直觉抓手**。
- 典型题错：回到标准层例题演示。
- 变式错：补迁移方法。
- 全对：进入拓展层或推荐巩固题，**提高信息密度，吐槽或幽默收束为简短避坑或总结**。

## 6. 输出验收标准

首批验收要求：

1. 内部必须完成主知识点或题目卡点定位；学生向输出不强制暴露定位字段。
2. 内部必须判断当前讲解层级及原因；学生向输出不强制说明层级名称。
3. 内部必须判断本轮知识类型；学生向输出不强制暴露类型名称。
4. **默认必须体现安全版暴躁老哥风格：口语化、短互动、吐槽题目/符号/易错点但保护学生；并选择一种教学动作。**
5. 必须包含前置知识处理。
6. 每轮必须包含一个微例、微判断或下一步检查点；不要求首轮完整例题。
7. 易错提醒按学生反馈追加，不要求首轮必须包含。
8. 必须包含下一步动作，并在一个问题后停住。
9. 数据缺失时必须明确降级，不得假装已检索真实题库。
10. **讲解内容必须通过 `teaching-style-guide.md` 中禁止行为清单的检查。**
11. 学生向输出不得使用 emoji、表情符号、对勾/叉号图标或警示图标。
12. 学生向输出默认不使用讲义式标题、分隔线和长列表。
