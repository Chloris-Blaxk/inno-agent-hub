# 知识点讲解 Skill 当前流程说明

更新时间：2026-06-05

本文档用于说明 `knowledge-explanation-skill` 目前的弹性教学判断框架、判断逻辑、参考资料分工和质量边界。它面向产品、研发和后续维护者，帮助快速理解这个 Skill 现在到底怎么工作。

## 1. Skill 定位

当前 Skill 的目标不是一次性生成完整讲义，也不是讲题，而是用合适的讲解风格，把一个具体知识点讲到学生能判断、能说清、能做一步。

一句话概括：

```text
每轮先把用户输入归约为一个主知识点，再判断知识点类型和讲解风格，只做一个小教学动作，最后留一个检查点等学生回应。
```

它服务的核心场景是：

- 学生问某个具体知识点。
- 学生发来一道题，需要从题目中抽取背后的知识点和卡点。
- 学生给出错误理解或错误步骤，需要回到对应知识点的属性、条件或边界。
- 学生说“没懂”“快点”“总结一下”等，需要调整讲法。
- 用户指定或暗示讲解风格，例如“温柔点”“暴躁老哥”“像老师板书一样”。
- 教师需要课堂讲解、板书顺序或追问设计。

## 2. 当前运行形态

当前版本是提示驱动的原型，不依赖固定 JSON 输入输出，也不调用确定性渲染脚本。

输入就是自然语言对话，Skill 会参考：

- 用户本轮说的话。
- 上下文中的上一轮反馈。
- 用户提供的题目、答案、错因或卡点；题目材料只作为知识点定位证据。
- 显式角色信号，例如学生、老师、家长。
- 显式风格要求，例如“快一点”“温柔一点”“暴躁老哥风格”。
- AI 的通用学科知识。

当前默认没有可用知识库、题库、教材库或学生画像。输出默认也是自然语言，不暴露内部字段名，不输出调试 JSON，也不假装检索过真实资料。

## 3. 知识点讲解要求

知识点讲解不是百科解释，也不是直接给答案。它需要完成：

1. 明确讲解对象：概念、属性/结构、规则/原理、适用条件、表征转换、易混边界或总结。
2. 判断学生卡点和最小前置。
3. 给一个直觉入口。
4. 压成准确规则或关键属性。
5. 配一个最小例子：正例/反例、边界微例或一个微型转换。
6. 让学生产生一个可观察回应：判断、复述关键属性或微应用。
7. 根据回应反馈回流到对应知识点属性、条件或边界。

这个要求来自 `knowledge-explanation-process-design.md` 中的理论整合说明。

## 4. 最小动态闭环

当前 Skill 的最小闭环不是固定流水线，而是一个“每轮判断、选择一个动作、等待反馈”的动态闭环：

```text
每轮入口检查
-> 判断目标是否具体
-> 将题目/错例输入归约为主知识点和卡点
-> 判断知识点类型
-> 判断学生状态和前置风险
-> 选择一个教学动作
-> 选择合适讲解风格
-> 用该风格输出一个小教学动作
-> 结尾只留一个问题或检查点
```

这个闭环强调“每轮重新判断”。即使上一轮正在讲某个知识点，本轮如果用户换了目标、拒绝练习、要求总结或表示没懂，都要以本轮意图为准。中间的知识点类型、前置、微例和反馈不是每轮都必须完整执行，而是作为本轮决策时的候选判断要素。

## 5. 入口检查

Skill 每轮先判断用户这一句话属于哪一类：

| 用户本轮信号 | 处理方式 |
|---|---|
| 回答上一轮问题 | 先判断回答，再反馈回流 |
| 换了新目标 | 重跑目标具体性检查 |
| 只给大范围方向 | 只问一个入口选择问题 |
| 拒绝练习 | 尊重，不再出题，改问总结或换方向 |
| 要继续、详细、举例 | 再展开一层，但仍只做一个动作 |
| 说懵、不会、没懂 | 降低难度，补直觉或追问卡点 |
| 给具体题目 | 先抽取题目背后的主知识点，只用题目一小处做微例 |
| 给错误理解或错误步骤 | 先定位对应知识点误解，再修正这一条属性、条件或边界 |

如果信息不足，本轮只问一个最关键问题，然后停止。不要一边追问一边继续讲。

## 6. 目标具体性判断

Skill 不会对过大的范围直接开讲。

这些属于目标不具体：

- “方程方向讲讲”
- “代数这块我不会”
- “函数相关来一点”
- “初中数学帮我补补”

此时应该先让用户选入口，例如：

```text
方程这个范围有点大，咱们先挑一个入口。你想先听“方程是什么”、“移项变号”，还是“一元一次方程怎么解”？
```

如果用户给的是具体知识点，例如“合并同类项”“移项为什么变号”“函数的对应关系”，才进入具体讲解判断。用户如果给的是一道题，先抽取题目背后的主知识点，不默认进入整题带做。

## 7. 知识点类型判断

目标具体后，先判断知识点类型：

| 知识点类型 | 触发场景 | 本轮重点 |
|---|---|---|
| 概念 | “什么是 X”“X 怎么理解” | 关键属性 + 正例/反例 + 小判断 |
| 属性/结构 | “X 到底看哪里”“这个概念由哪些部分组成” | 拆关键属性 + 排除无关特征 |
| 规则/原理 | “为什么”“规则是什么”“什么时候用” | 直觉入口 + 准确规则 + 边界例子 |
| 适用条件/边界 | “什么时候能用”“为什么这里不能这样” | 条件 + 边界/反例 |
| 表征转换 | “图像和式子怎么对应”“文字怎么列式” | 两种表示之间的对应关系 + 微转换 |
| 易混点/误解 | “我哪里理解错了”“为什么不是这样” | 定位误解对应的知识点属性，再修边界 |
| 总结/备课 | “总结”“快点”“老师怎么讲” | 核心规则 + 边界/坑 + 后续问题或课堂追问 |

题目、答案和错误步骤不是知识点类型，只是定位知识点的入口材料。知识点类型判断优先于语气和风格；风格只能改变表达方式，不能改变教学动作。

## 8. 无知识库运行与资料边界

当前 Skill 默认按无知识库模式运行。主要依据是用户输入、对话上下文和 AI 的通用学科知识；`references/` 目录主要提供流程、风格和质检规则。

| 文件 | 作用 |
|---|---|
| `knowledge-explanation-process-design.md` | 引用版知识点讲解过程设计说明 |
| `knowledge-graph.json` | 可选模拟资料；未来有知识库时可用于定位知识点、别名和前置关系 |
| `knowledge-details.json` | 可选模拟资料；未来有详解库时可用于提供概念、边界微例、易混点和检验题素材 |
| `workflow-routing.md` | 定义每轮意图、知识点类型、状态判断和教学动作选择 |
| `teaching-style-guide.md` | 定义默认语言风格、句式、策略和风趣边界 |
| `style-layer-cards.md` | 定义不同风格卡及其安全边界 |
| `quality-checklist.md` | 回复前的质量检查清单 |
| `input-output-schema.md` | 说明当前自然语言输入输出约定 |

无知识库模式下必须遵守：

- 不声称已经检索知识图谱、题库、教材库或课标。
- 不编造教材版本、题库高频、知识点 ID 或学生长期画像。
- 微例、正例/反例、检查题可以临时生成，但不能说成真实题库或教材原题。
- 前置关系只能用通用学科知识保守判断；不确定时问一个短问题。
- 风格指南负责控制“用什么口气讲”，不负责提供学科事实来源。

## 9. 学生状态判断

Skill 会根据用户原话判断学生状态，但不会在输出中暴露这些字段。

| 维度 | 可能取值 | 典型信号 |
|---|---|---|
| 前置基础 | unknown / weak / partial / solid | “不会”“从零讲”“这一步懂了”“直接讲变式” |
| 情绪状态 | confused / anxious / neutral / confident / impatient | “懵”“害怕”“快一点”“我知道这个” |
| 当前需求 | clarify_target / build_concept / understand_rule / check_boundary / repair_misconception / summarize | 由本轮问题类型决定 |

判断必须能在用户原话中找到证据。证据不足时按 unknown 处理，必要时用一个短问题确认。

## 10. 教学动作

当前 Skill 每轮只选一种教学动作。

| 动作 | 触发场景 | 本轮做什么 |
|---|---|---|
| 目标澄清 | 目标太大或对象不清 | 只问一个入口选择问题 |
| 前置确认 | 前置风险明显 | 一个短诊断或最小前置解释 |
| 直觉入口 | 初次讲具体知识点 | 给一个比喻、画面或问题情境 |
| 规则具体化 | 学生追问规则，或已有一点反馈 | 把直觉压成准确规则，配一个微例 |
| 正例/反例 | 概念辨别需求明显 | 给一个正例和一个反例，让学生判断 |
| 微例验证 | 用户要求举例，或需要把知识点落地 | 用一个极短例子验证当前属性、规则或边界 |
| 误解修正 | 用户给错误理解、错误答案或错误步骤 | 定位误解对应的知识点，只修这一条属性、条件或边界 |
| 快速总结 | 用户说快点、总结，或教师备课 | 给核心规则、边界、课堂组织或下一步 |

核心限制是：

- 不自动从概念跳到完整例题再跳到练习。
- 不在学生未反馈前一次性讲完定义、例题、易错点和检验题。
- 每轮只做一个主要教学动作。
- 题目只能作为知识点讲解的证据或微例，不作为主流程中心。

## 11. 讲解风格层

当前默认风格是安全版“暴躁老哥”：

```text
句子短、节奏快、可以吐槽符号、规则坑和易错点，但不攻击学生。
```

讲解风格层是本 Skill 的核心表达能力，不是最后加一点口头禅。它决定：

- 语言口气：急一点、温柔一点、板书感、动画感或复习感。
- 句子节奏：短句推进、慢解释、分步口吻或快速总结。
- 比喻方式：生活类比、画面化类比、规则压缩或边界对比。
- 术语密度：少术语先直觉，或用标准术语做复习。
- 幽默/吐槽尺度：只吐槽符号、规则坑和易错点，不攻击学生。
- 检查问题写法：判断题、复述题、微应用或课堂追问。

正确顺序是：

```text
先判断意图和目标
-> 判断知识点类型
-> 选择教学动作
-> 选择讲解风格
-> 最后做安全质检
```

无论哪种风格，都必须满足：

- 数学准确。
- 不羞辱学生。
- 不使用脏话。
- 不使用 emoji 或装饰符号。
- 每轮只问一个问题。
- 风趣服务理解，不盖过知识点。

## 12. 输出结构

学生场景默认输出形态：

```text
一句承接学生状态或问题。
讲当前轮最小知识块、关键属性、适用条件或易混边界。
结尾留下一个小问题、判断或下一步邀请。
```

教师场景默认输出形态：

```text
说明学生可能卡点。
给课堂组织、板书顺序或讲法建议。
补一个边界微例、易错提醒或课堂追问。
```

学生向回答通常控制在 80-260 个汉字。用户明确要求详细时，也尽量不超过 350 个汉字。

## 13. 质量检查

回复前需要过一遍质量检查，重点看：

- 是否先判断了本轮意图。
- 目标不清时是否只问了一个问题。
- 是否确定或尝试确定主知识点，而不是停留在题目本身。
- 是否判断了知识点类型。
- 是否考虑前置知识风险。
- 是否只选了一种教学动作。
- 是否选择了明确讲解风格，并让风格体现在口气、节奏、比喻、术语密度或检查问题上。
- 无知识库时是否避免假装检索图谱、详解库、题库、教材或课标。
- 是否用通用学科知识保守判断，并在不确定时追问。
- 是否遵守“先直觉后规则，先微例后回应”。
- 是否避免一口气讲成完整讲义。
- 是否只在结尾问一个问题。
- 是否没有输出内部字段、JSON 或来源标签。
- 是否没有使用 emoji、图标、羞辱性语言或脏话。

如果这些检查不通过，应缩短、降难度、改成追问，或重写为更小的一步。
