# 质量检查清单

## P0 必须通过（学术诚信 + 教师可读性）

### 学术诚信

- 输出必须包含 `materialDigests`、`materialClusters`、`researchTrajectory`、`topicCandidates`、`topicEvaluationReport` 和 `qualityReport`。
- 总结性选题必须引用用户材料中的 `materialId`。
- 存在用户材料时，`materialClusters` 必须能回链到真实 `materialId`，并说明主题缺口和可转化选题角度。
- `researchTrajectory` 必须说明已有积累阶段、主导主题、未来深耕路径和风险。
- 不得虚构教师已有论文、课题、获奖、数据或成果。
- 每个选题必须包含 `topicTitle`、`topicType`、`existingBasis`、`basisGap`、`differentiation`、`feasibility`、`keywords`。
- 每个选题必须说明至少 1 条风险或下一步资料清单。
- `basisGap` 必须说明当前基础、目标申报要求、缺口和升级路径。
- `differentiation` 必须说明最近似立项题、相似度、风险等级和差异化策略。

### 教师可读性

- [ ] 选题以「选题 1：《XXX》」为主标识，topicId 仅出现在括号或脚注中。
- [ ] 总结性/规划性选题用 🔵/🟢 标记，一眼可区分。
- [ ] 评分用 ⭐ 星级 + 一句通俗解释，不裸写 JSON 数值或权重。
- [ ] 材料回链用材料标题（如「你的《异分母分数加减法错因分析课例》」），不用 mat-XXX ID。
- [ ] 研究轨迹阶段用中文 + emoji（📭 材料较少 / 📚 积累中 / 🎯 方向成形 / ✅ 证据充分）。
- [ ] 差异化检查用自然语言对比，不用裸写 `similarityScore: 0.5`。
- [ ] 可行性风险说人话（「需要 XX」「可能要先解决 YY 问题」）。
- [ ] 全文用「你（李老师）」称呼教师，不用「用户」。
- [ ] dkgEvidence 和 scoreBreakdown 不直接照搬 JSON 进教师可读输出，必须转成自然语言。

## P1 建议通过

- 选题题目不应过大，例如「核心素养下小学数学教学研究」。
- 规划性选题应说明政策热点或学校实践问题的匹配关系。
- 同一批选题之间应有差异，不只是关键词替换。
- 推荐选题应与教师可投入周期匹配。
- 总结性选题优先基于主题簇生成，而不是只复述单份材料。
- 向教师展示时，选题排序附带推荐理由（如「建议首选这个，因为你的材料几乎都能用上」）。

## 降级策略

- 材料不足：输出「待补材料清单」，不硬生成总结性选题。向教师解释：「目前你的材料还比较少，我先帮你规划几个未来可以深耕的方向，等你补充了 XX 材料之后，我们可以再精确选题。」
- 教师画像缺字段：保留假设并在 `qualityReport.warnings` 中提示。向教师确认：「我看到你还没提供 XX 信息，我先按常见情况假设，你看对不对？」
- 政策热点未命中：不影响生成，但不得声称政策高度契合。
