# 经典例题选择规则

## 目标

经典例题不是“随便举一题”，而是要服务当前知识点定位、层级判断和即时检验闭环。当前默认没有真实题库，因此更准确地说，学生向讲解里使用的是“临时微例”或“生成样例”，不是可声称来源的经典题库例题。

## 选择优先级

1. 直接命中当前主知识点。
2. 难度与当前层级一致。
3. 步骤短、结构清楚、便于口头讲解。
4. 能暴露该知识点最典型的错法。
5. 有利于衔接即时检验题。

## 分层选题规则

### 入门层

- 题目结构尽量单一。
- 数值和条件保持简单，避免多层嵌套。
- 优先让学生看见“为什么先补前置知识”。

### 标准层

- 选择最能代表标准方法的题。
- 步骤必须完整，方便抽取规范做法。
- 允许包含一个常见陷阱，但不能把陷阱当主难点。

### 拓展层

- 优先使用变式题、对比题或迁移题。
- 题目必须建立在典型题已经稳定掌握的前提上。
- 不引入超纲知识或竞赛技巧。

## 分层难度建议

| 层级 | 难度建议 |
|---|---|
| `entry` | 1-2 |
| `standard` | 2-3 |
| `advanced` | 3-4 |

## 来源标记

教师或调试场景可以显式标记来源：

- `retrieved`：来自真实题库、教材或题例资源。
- `generated_sample`：系统按规则生成的样例。

当前无真实题库时：

- 允许生成样例或微例。
- 学生向输出不需要暴露 `generated_sample` 字段。
- 教师或调试场景必须在 `classicExample.sourceType` 中标为 `generated_sample`。
- 不得写成“教材原题”“历年真题”“题库高频”等误导性来源。

## 例题对象最低要求

```json
{
  "id": "example-001",
  "sourceType": "generated_sample",
  "stem": "题干",
  "answer": "答案",
  "solutionSteps": ["步骤1", "步骤2"],
  "whyTypical": "为什么它代表这一类题"
}
```

如有数据底座，建议额外保留以下元数据，方便后续和题库、错因标签联动：

- `knowledgePoint`
- `difficulty`
- `commonMistakeTags`

## 不合格例题

以下情况视为不合格：

- 和当前知识点关系弱，只是题材接近。
- 难度明显超出选定层级。
- 只有答案，没有步骤。
- 题目过长，导致讲解重点被背景信息淹没。
- 为了“显得高级”而使用偏题、怪题、冷门题。

## 典型性判定

一个合格的经典例题，至少同时满足以下条件：

- 只命中一个主知识点。
- 核心方法清楚可见。
- 步骤不被无关计算负担淹没。
- 能暴露至少一个易错点。
- 能自然衔接一题即时检验题。
