# 概念播种

提供“值得问什么的入口”，不要替学习者完成提问，也不要提前讲完整堂课。

## 播种流程

1. 读取 `learning-state.json`（如存在）和可用的 L1 学习者上下文，判断用户是在继续旧主题还是开始新主题。继续旧主题时优先呈现未验证或待复习的概念，不重复初始化；L1 中存在语义完全相同的概念时复用其规范 ID。
2. 从用户给出的主题、材料、目标和水平中确定范围。仅当这些信息不足以选出合适概念时，提出一个必要的澄清问题并停止；否则采用合理假设并用一句话说明。
3. 选择 3–5 个概念，按先修关系排序。优先选择：
   - 能支撑后续理解的基础概念；
   - 能揭示机制或概念间关系的枢纽；
   - 容易混淆、存在重要边界的概念；
   - 能迁移到新情境的概念。
4. 若用户提供了材料，只从材料及其必要先修知识中提炼，不虚构材料内容，也不扩展成无关知识清单。
5. 更新学习状态并呈现种子，然后把发问权交给学习者。

## 呈现格式

每个种子只给名称和一句入口，不给完整定义、长篇解释或预制问题：

```markdown
## <主题>的概念种子

1. **<概念>** — <它在这个主题中的作用或值得理解之处>
2. **<概念>** — <一句入口>
3. **<概念>** — <一句入口>

从一个概念开始，由你提出第一个问题。我会先回答你实际问的这一问。
```

不要在结尾附测验题、问题清单或“你觉得呢”。学习者若说不会提问，只提供未代填的句架，例如“为什么……？”“……与……有什么区别？”“如果改变……会怎样？”“它在什么条件下不成立？”，随后等待学习者自己补全一个问题。

## 初始化学习状态

首次播种时创建 `learning-state.json`；更换主题时追加新主题并保留旧主题。使用以下结构，保持字段和枚举稳定：

```json
{
  "version": 1,
  "active_topic_id": "statistics.bayes",
  "topics": [
    {
      "id": "statistics.bayes",
      "name": "贝叶斯推断",
      "goal": "学习目标",
      "source": "用户材料或主题描述",
      "active_concept_id": null,
      "concepts": [
        {
          "id": "statistics.bayes.posterior-probability",
          "name": "后验概率",
          "status": "seeded",
          "questions_since_check": 0,
          "total_questions": 0,
          "highest_question_depth": "D0",
          "mastery_evidence": "E0",
          "misconceptions": [],
          "pending_verification": null,
          "last_verified_at": null
        }
      ]
    }
  ],
  "updated_at": "<ISO 8601 时间>"
}
```

- `status` 只使用 `seeded | exploring | checking | verified | needs-review`。
- 为主题和概念使用**跨工作区稳定的语义 ID**，不要使用 `topic-001`、`concept-001` 等顺序号。ID 使用小写 ASCII 点分路径：主题采用 `<domain>.<topic>`，概念在其后追加规范语义名，例如 `statistics.bayes.posterior-probability`。
- 优先采用学科中通行的英文规范术语；读取到已有 L1 概念时，仅在语义与范围一致的情况下复用其 ID。同义显示名称共用一个 ID；相同名称在不同学科中含义不同时使用不同路径。显示名称始终保存在 `name`，不要依靠 ID 反推名称。
- 后续只改显示名称时不要换 ID；概念的语义范围实质变化时创建新 ID，不要把旧掌握度合并进来。
- 重新播种同一主题时，保留已有计数、掌握证据和误区；仅增加新概念或合并明确重复项。
- 将 `active_topic_id` 指向本次主题；在学习者实际选择或提问前，让 `active_concept_id` 保持 `null`。

若 `question-journal.md` 不存在，只创建标题“# 追问日志”和一句说明“本文件仅追加问题与检验证据；问题深度不等于掌握程度。”此时不要替学习者制造问题记录。
