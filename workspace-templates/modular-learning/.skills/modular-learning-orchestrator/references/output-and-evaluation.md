# Output And Evaluation

## Default Output

Answer the learner's immediate question in a few short paragraphs. Keep route codes, concept
numbering, and the internal block metaphor out of ordinary replies. Do not append a fixed
checklist or a five-option menu to every message.

When the learner explicitly requests an overview, show a small orientation map. For a substantial
lesson, offer one concise next choice at a useful stopping point. The structured format in
SKILL.md is optional and applies only to structured learning requests.

Only report a Wiki update after inspecting a tool result that confirms the relevant pages or
relationships were written. Archive acceptance or a progress event alone is insufficient.

## Acceptance Cases

- Sparse memory: read L1 and L2, show a small map, teach one independent block, offer context rather than forcing it.
- Immediate interruption: answer the new learner question first and keep the original block as anchor.
- Reconnection: use L3 to recover the checkpoint; if missing, state that and restart from known facts.
- Lateral expansion: use an L2-grounded adjacent concept, label `supported`, `analogical`, or `speculative`, then bridge back.
- Observed learning: write evidence only after an actual learner action; exposition alone is `exposure`.
- Missing tools or empty memory: continue using known information without inventing history or writes.
- Scenario refusal: keep explaining the independent concept and offer other uses without forcing a story.

## Checklist

- [ ] A block remains useful without its story.
- [ ] More than one use is shown when evidence permits.
- [ ] Context is selected from evidence or explicit choice.
- [ ] Every substantial turn has a recoverable checkpoint.
- [ ] L3 restores continuity without inventing mastery.
- [ ] Low energy produces a connected lighter branch, not random trivia.
- [ ] Direct questions interrupt the planned route.
