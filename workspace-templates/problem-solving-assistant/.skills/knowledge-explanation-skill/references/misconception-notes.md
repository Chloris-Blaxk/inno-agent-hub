# 易错点说明

## 输出目标

易错点不是罗列“可能会错”，而是要说明：

1. 错在哪里。
2. 会表现成什么症状。
3. 为什么会这样错。
4. 下一步怎么修。

## 输出结构

每条易错点使用以下结构：

```json
{
  "mistake": "错误名称",
  "symptom": "学生会怎么做错",
  "cause": "导致该错误的原因",
  "fix": "修复建议或提醒语"
}
```

## 优先覆盖的易错类型

1. 前置知识未补牢引发的错法。
2. 当前典型例题中最可能出现的错步。
3. 容易与相邻知识点混淆的判断边界。

## 写法要求

- `mistake` 要短，能一眼看懂。
- `symptom` 要具体，最好能对应学生常见说法或错步。
- `cause` 要回到知识点本身，不写成“粗心”。
- `fix` 要能直接转成教师提醒语或学生操作习惯。
- 单轮建议输出 1-3 条，优先绑定当前例题，不要一次性堆太多。

## 示例

```json
[
  {
    "mistake": "把分母直接相加",
    "symptom": "把 1/2 + 1/3 算成 2/5",
    "cause": "没有先统一分数单位，机械套用了“分子相加”的表面规则。",
    "fix": "每次下笔前先检查两个分数单位是否一样大，不一样就先通分。"
  },
  {
    "mistake": "移项时只改一个地方",
    "symptom": "把 x + 5 = 12 写成 x = 12 + 5",
    "cause": "把移项当成“搬家变号”，没有理解本质是等式两边同时做相反操作。",
    "fix": "先用“等式两边同时减去 5”表述，再简化成移项。"
  }
]
```

## 不合格写法

以下写法不合格：

- 只写“学生容易粗心”。
- 只写“注意别错”。
- 只给结论，没有说明症状或修复动作。
- 易错点和当前知识点无直接关系。
