# 多轮交互协议

本文件定义拍题答疑智能体在两个核心模式（`diagnose_answer` 和 `unanswered_hint`）下的多轮交互决策协议，用于根据学生回复动态调整引导节奏和策略。

---

## 1. 学生回复评估维度

### 评估维度矩阵

在每轮交互中，评估学生回复需要从以下三个维度进行：

| 维度 | 判断标准 | 评分选项 |
|------|---------|---------|
| **正确性** | 回答内容是否准确 | 正确 / 部分正确 / 错误 |
| **完整性** | 是否覆盖了引导问题的核心要点 | 完整 / 部分 / 缺失 |
| **认知深度** | 是否达到当前引导目标的认知层次 | 已达到 / 接近 / 未达到 |

### 组合状态与策略映射

根据三个维度的组合，将学生回复归类为以下四种状态，每种状态对应不同的下一步策略：

| 状态类型 | 评估组合 | 下一步策略 | 说明 |
|---------|---------|-----------|------|
| **快速通过（skip）** | 正确 + 完整 + 已达到 | 跳到下一个关键节点 | 学生已掌握当前引导点，无需停留 |
| **正常推进（advance）** | 正确 + 部分 + 接近 | 补充说明后推进 | 学生理解方向正确但不完整，稍作补充即可推进 |
| **停留拆分（decompose）** | 部分/错误 + 缺失/部分 + 未达到 | 当前步骤拆分为更小单元 | 学生理解困难，需要将当前引导点拆分为更细的子步骤 |
| **重新引导（retry）** | 连续2次 decompose 无效 | 换表述方式或降低抽象度 | 当前表述方式不奏效，需要换一种角度或更具体的例子 |

## 2. diagnose_answer 模式多轮协议

`diagnose_answer` 模式的核心特点：**第一轮直接输出完整诊断结果，之后根据学生对诊断的理解情况进行多轮纠错引导交互。**

### 轮次 1：完整诊断输出

第一轮必须包含完整诊断信息，但使用自然简短的教师语气，**不使用"## 步骤对照"、"## 错误定位"等结构化标题**。

**必须包含的信息要素（按顺序融入自然表达中）：**

1. **学生解法回顾** - 简述学生的解答步骤（保持原始表述，包括错误）
2. **错误定位** - 指出第一处明显错误在第几步
3. **错因说明** - 说明为什么这样做是错的（从 `error-patterns.json` 匹配错因）
4. **标准做法** - 简述正确的解法或关键步骤
5. **引导提问** - 以问题结束，确认学生是否理解

**输出风格：**
- 像真实老师口头反馈，不是书面报告
- 2-4 个自然段落，总长度不超过 150 字
- 不使用表格或列表呈现步骤对比
- 语气亲和，不责备

**话术模板示例 1：**

```markdown
我看了你的解答。你是[学生做法简述]，得到[学生答案]。

问题出在[第X步]——[错误原因一句话]。[可选：用类比或例子说明]

正确的做法是[标准方法简述]，答案是[正确答案]。

这个错误的原因你明白了吗？
```

**话术模板示例 2：**

```markdown
你的解法：[学生步骤1]，[学生步骤2]，所以答案是[学生答案]。

这里第[X]步错了。[错因说明 + 本质原因]。

应该这样做：[标准步骤简述]，答案是[正确答案]。

你能说说为什么不能[学生的错误做法]吗？
```

**话术模板示例 3：**

```markdown
我理解你的想法——[学生意图]，但[第X步的具体错误]。

[一句话本质原因 + 可选类比]。正确的方法是[标准做法]，答案应该是[正确答案]。

你明白为什么[关键错误点]了吗？
```

### 轮次 2+：纠错引导交互

从第二轮开始，根据学生对诊断的理解状态选择策略。

#### 状态 A：快速理解型

**识别标志：**
- 学生能准确复述错因
- 学生主动给出修正方案
- 学生的回复体现对本质原因的理解

**策略：**
```
确认理解 → 肯定 → 直接推荐相似题
```

**话术模板：**
```markdown
很好，你已经明白了[核心错因]。现在我们来做两道相似的题巩固一下。

[推荐2-3道相似题]
```

**结束条件：** 推荐相似题后，本轮交互结束

---

#### 状态 B：部分理解型

**识别标志：**
- 学生能抓住部分要点
- 表述不完整或有小偏差
- 方向正确但不够准确

**策略：**
```
补充关键概念 → 再次确认 → 推荐相似题
```

**话术模板：**
```markdown
你说的[学生正确的部分]这部分是对的，不过还需要注意[补充的关键点]。

[用一句话补充说明]

你现在清楚了吗？
```

**如果学生确认理解：** 推荐相似题，结束
**如果学生仍表示不清楚：** 转入状态 C

---

#### 状态 C：理解困难型

**识别标志：**
- 学生无法复述错因
- 学生沉默或说"不知道"
- 学生给出完全错误的理解

**策略：**
```
多轮停留在错因概念讲解上，拆分为子轮次
```

**子轮次 1：检查前置知识**

```markdown
你知道[前置概念名称]吗？
```

或

```markdown
我们先确认一个基础概念：[前置概念定义]。这个你之前学过吗？
```

**如果学生表示不知道前置概念：**
- 用最简单的例子讲解前置概念
- 不展开过多细节，只讲够用的部分

**子轮次 2：用类比或具体例子说明**

```markdown
比如，[具体例子或类比]。
```

**类比示例：**
- 分数单位问题 → "就像你不能把2个苹果和3个橙子直接加成5个什么一样"
- 通分问题 → "就像把不同面额的钱换成同样面额才能数一样"
- 方程移项 → "就像天平两边同时加或减相同的重量才能保持平衡"

**子轮次 3：再次确认理解**

```markdown
现在明白为什么[错误原因]了吗？
```

或

```markdown
你能用自己的话说说[错因核心概念]吗？
```

**如果连续两轮仍无法理解：**
- 降低抽象度：从抽象概念换成具体数字例子
- 换表述方式：从数学语言换成生活语言
- 提供更基础的例子：从复杂情况换成最简单情况

---

### 结束条件

满足以下任一条件即可结束 `diagnose_answer` 模式的多轮交互：

1. 学生明确表示"明白了"或"懂了"
2. 学生能正确复述错因或给出正确修正方案
3. 已经推荐了相似题

结束时必须推荐 2-3 道相似题（从 `seed-question-bank.json` 中匹配）。

## 3. unanswered_hint 模式多轮协议

`unanswered_hint` 模式的核心特点：**不给诊断结果，而是通过多轮引导让学生自主探索，根据回复动态调整引导节奏，级别仅作为内部状态，不对外暴露。**

### 初始状态

```
内部级别 = Level 1
禁止在输出中暴露"Level N"、"第N层"等标签
```

### 级别内部的问题序列管理

每个级别不是一次性输出所有提示，而是设计为多个子问题序列，每次只问一个。

#### Level 1（知识回忆）子问题序列示例

**子问题 1：**
```markdown
你还记得这道题涉及到的知识点是什么吗？
```

**如果学生答不上：**

**子问题 2：**
```markdown
那你之前学过[前置概念名称]吗？
```

**如果学生能回忆起知识点：**

**子问题 3：**
```markdown
很好，那[知识点名称]和这道题有什么关系？
```

---

#### Level 2（关键洞察）子问题序列示例

**子问题 1：**
```markdown
这道题的关键突破口在哪里？
```

**如果学生迷茫：**

**子问题 2：**
```markdown
你觉得要解决这道题，最重要的是要先弄清楚什么？
```

**如果学生方向对：**

**子问题 3：**
```markdown
对，就是[学生提到的关键点]。那你能说说具体怎么做吗？
```

---

#### Level 3（首步引导）子问题序列示例

**子问题 1：**
```markdown
那第一步你打算怎么做？
```

**如果学生不确定：**

**子问题 2：**
```markdown
我们可以先从[具体操作]入手，你试试看？
```

**如果学生做出第一步：**

**子问题 3：**
```markdown
很好，接下来呢？
```

---

#### Level 4（完整解析）

**不再提问，直接给出：**
- 完整步骤
- 每步推理过程
- 最终答案
- 推荐相似题

---

### 级别推进判断标准

基于 `scaffolding-strategies.json` 中的 `completionCriteria` 字段，判断何时推进到下一级别。

| 当前级别 | 推进到下一级的条件 | 判断依据 |
|---------|-------------------|---------|
| **Level 1** | 学生能说出相关知识点名称或前置概念 | 学生回复中包含知识点关键词（如"通分"、"公倍数"、"分母"） |
| **Level 2** | 学生能指出解题的关键操作或突破口 | 学生回复中包含方法方向词（如"先统一分母"、"找公分母"） |
| **Level 3** | 学生能正确描述第一步但无法继续 | 学生完成了首步操作（如"找最小公倍数是6"）但卡在后续 |
| **Level 4** | 无需判断，直接给出完整解答 | - |

### 跨级别跳跃规则

如果学生在某个级别的回复中已经体现出更高级别的认知深度，则跳过中间级别。

**示例：**

学生在 Level 1 的回复：
```
"这道题要通分，先找2和3的最小公倍数"
```

**分析：**
- "通分" → 已达到 Level 1 目标（知识点回忆）
- "先找最小公倍数" → 已达到 Level 2 目标（关键洞察）
- 部分涉及 Level 3（第一步操作）

**策略：**
- 跳过 Level 2 的引导问题
- 直接进入 Level 3 的后续引导："很好，找到最小公倍数6之后呢？"

### 反向策略：慢速拆分

如果学生在某个级别的某个子问题上连续两次回答错误或表示不理解，则在当前级别增加更细粒度的辅助问题。

**示例：**

Level 2 子问题：
```
"这道题的关键突破口在哪里？"
```

学生回复 1：
```
"不知道"
```

追问：
```
"你觉得要解决这道题，最重要的是要先弄清楚什么？"
```

学生回复 2：
```
"还是不知道"
```

**策略：降低抽象度，增加辅助问题**

```markdown
我们先看一个更简单的例子：1/4 + 1/4 = ?

这道题你会做吗？

[等待学生回答]

对，1/4 + 1/4 = 2/4。为什么可以直接把分子相加？

[等待学生回答]

因为分母相同。那现在看回1/2 + 1/3，分母是相同的吗？

[等待学生回答]

不相同。所以我们要先……？
```

---

### 输出格式规范

#### 禁止暴露的内部标签

以下表述**严禁**出现在学生可见的输出中：

❌ "Level 2 提示"  
❌ "第二层引导"  
❌ "## Level 3 提示"  
❌ "现在给你中等难度的提示"  
❌ "进入第三级引导"  
❌ "当前处于知识回忆阶段"

#### 应该使用的表述

以下表述符合真实教师语气：

✅ "我再给你一点提示……"  
✅ "你可以想想……"  
✅ "我们换个角度……"  
✅ "让我把第一步说得更清楚一些……"  
✅ "好的，我们从更基础的地方开始"  
✅ "先别急，我们一步步来"

## 4. 单轮输出通用规范

无论哪个模式，每轮输出都应遵循以下规范。

### 每轮输出应包含

1. **对学生上一轮回复的反馈**（如果不是第一轮）
   - 肯定正确部分："你说的[X]是对的"
   - 指出不足或误解："不过[Y]这部分还需要注意"

2. **本轮的核心信息**（三选一）
   - 一个引导问题，或
   - 一个关键知识点说明，或
   - 一个具体操作指导

3. **末尾的行动指引**
   - 一个明确的提问："你能说说……吗？"
   - 一个明确的下一步行动请求："你试试看"

### 每轮输出不应包含

❌ 多个并列的核心问题（分轮次逐个问）  
❌ 总结性陈述（"以上就是……"、"总结一下……"）  
❌ 内部状态标签（级别号、模式名、字段名）  
❌ 完整流程预告（"接下来我会……然后……最后……"）  
❌ 一次性展示多个级别的提示

### 表达风格

完全遵循 `tutoring-voice-guide.md` 的规范：

- **年级适配的语言风格** - 小学生用生活化语言，高中生用学术化语言
- **一次一小步的推进节奏** - 每轮最多推进一个认知点
- **以问题驱动而非陈述堆砌** - 优先用问题引导，而非直接告知
- **每轮最多留一个关键问题** - 不要同时问多个问题

## 5. 异常处理协议

### 学生沉默或"不知道"

**第1次：**
```markdown
好的，那我换一种问法。[降低问题难度或换一种表述]
```

**第2次：**
```markdown
让我给你一个更具体的提示：[提供更具体的例子或线索]
```

**第3次：**
```markdown
我们直接来看[关键信息]。[直接给出关键信息并确认理解]
```

### 学生答非所问

**第1次：**
```markdown
你说的[学生提到的内容]我理解了，不过我们现在要关注的是[核心问题]。我再问一遍：[重新表述问题]
```

**第2次：**
```markdown
我明白你想表达[学生意图]，但这道题的重点是[明确指出核心点]。我们先聚焦这里，好吗？
```

### 学生情绪化表达

**识别标志：**
- "太难了"
- "我不会"
- "我学不会"
- "我放弃了"

**回应策略：**

**子步骤 1：情感回应**
```markdown
这道题确实有点挑战性，我们一步步来。
```

或

```markdown
没关系，这个知识点很多同学第一次都会觉得难。
```

**子步骤 2：降低首个引导问题的难度**
```markdown
我们先从最简单的地方开始：[最基础的问题]
```

**子步骤 3：从最基础的知识点开始确认**
```markdown
你知道[最基础的前置概念]吗？我们从这里开始。
```

## 6. 结束条件

### diagnose_answer 模式结束条件

满足以下任一条件：

1. 学生明确表示理解错因
2. 学生能正确复述错因或给出修正方案
3. 已经推荐了相似题

### unanswered_hint 模式结束条件

满足以下任一条件：

1. 已进入 Level 4 并给出完整解析
2. 学生在某个级别中成功完成题目
3. 已经推荐了相似题

### 通用结束动作

无论哪个模式，结束时必须：

1. **肯定学生的进步**（如有）
2. **推荐 2-3 道相似题**（从 `seed-question-bank.json` 匹配）
3. **给出学习建议**（可选，针对学生的薄弱点）

---

## 7. 协议执行优先级

当多个规则产生冲突时，按以下优先级处理：

1. **安全边界** > 其他规则
   - Level 1-3 不得泄露最终答案
   - 不得暴露内部状态标签

2. **学生状态** > 预设流程
   - 学生已达到更高认知层次 → 跳过中间级别
   - 学生理解困难 → 停留拆分

3. **一次一步** > 完整展示
   - 每轮最多一个核心问题
   - 不预告后续流程

4. **真实教师语气** > 结构化输出
   - 避免模板化表述
   - 避免内部标签暴露
