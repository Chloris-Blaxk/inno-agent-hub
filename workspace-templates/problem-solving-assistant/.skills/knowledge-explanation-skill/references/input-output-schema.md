# 交互输入输出约定

当前 Skill 是提示驱动的教学判断 Skill，不再要求用户或 Claude Code 构造固定 JSON 请求，也不再输出固定 JSON 结构。

## 输入

输入就是当前自然语言对话。Claude Code 可以利用当前会话上下文，包括：

- 用户本轮问题。
- 上一轮学生/教师的自然语言反馈。
- 用户给出的题目、解题过程、错因描述。
- 用户显式说明的年级、教材、角色和要求。
- AI 的通用学科知识。

当前默认没有可用知识库、题库、教材库或学生画像。不需要传 `studentLevel`、`preferredMode`、`stepState` 等结构化字段。若这些字段出现在用户材料里，可以作为弱信号参考，但真实自然语言反馈优先。

## 内部判断

回复前在内部完成最小必要判断：

1. `target`：本轮主要知识点或题目卡点是什么。
2. `relatedKnowledge`：基于通用学科知识保守判断出的相关知识点和可能前置是什么。
3. `contentBasis`：本轮内容依据是什么，通常是用户材料 + AI 通用学科知识；若未来启用知识库，再记录真实资料来源。
4. `studentState`：学生是未知、薄弱、部分理解、已掌握，还是只是想快速复习。
5. `tone`：亲和慢讲、清晰规范、简洁直接、教师参考。
6. `teachingMove`：追问、补前置、补概念、讲一步例题、诊断错因、给练习、总结。

这些字段仅用于内部思考，不直接暴露给用户。

## 输出

默认输出自然语言，不输出 JSON。

学生场景不直接暴露 `retrieved`、`inferred`、`generated_sample` 等来源字段；若需要说明推断边界，用自然语言表达。教师参考或调试场景可以显式标记“临时生成样例”。无知识库时，不得暗示已经检索真实题库、教材或课标。

学生场景建议结构：

```text
先回应学生状态。
讲当前轮最小知识块或题目关键一步。
给一个小例子/判断/检查问题。
停下来等学生回复。
```

教师场景建议结构：

```text
说明学生可能卡点。
给教学组织或板书顺序。
补一个例题、易错提醒或课堂追问。
```

## 不做的事

- 不调用确定性渲染脚本。
- 不强制输出 `style`、`conversationAction`、`progressState` 等字段。
- 不自行编造结构化历史状态。
- 不自动推进多个阶段。
- 不把参考资料里的模板原样搬给用户。
- 不在学生端输出内部来源字段或调试字段。
- 不伪装成已经使用知识库、题库、教材库、课标库或学生画像。
