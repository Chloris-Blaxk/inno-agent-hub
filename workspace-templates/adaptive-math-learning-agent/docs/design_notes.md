# 设计说明

## 目标

在中小学数学范围内实现可追溯的诊断—验证—修复—迁移闭环，而不是把所有题型统一成“答案匹配”。系统既允许多解法，又通过评价分层控制开放题的结论强度。

## 六层职责

1. `math-task-structurer` 只负责把输入变成稳定任务结构并选择评价方式。
2. `math-reasoning-trace-analyzer` 负责核验路径、定位首个关键错误和记录初始证据。
3. `math-misconception-verifier` 负责控制变量探针和诊断状态变化。
4. `multi-representation-repair` 负责文字、符号、图像、表格、操作和情境之间的转换。
5. `adaptive-math-practice` 负责生成并自检练习，不负责提前确认误区。
6. `math-learning-progress-reporter` 只汇总已经存在的证据。

## 评价可靠性

- `deterministic`：数值、代数等可直接核验的问题；
- `rubric`：证明、建模表达等依据明确规则评价的问题；
- `model`：只有结构判断、缺少完整标准时的保守评价；
- `unknown`：条件或内容不足，不能评价。

评价方式决定结论强度。模型评价不能伪装成确定性证明；没有原始过程时不能断言具体哪一步出错。

## 多解法原则

参考答案只是可用路径之一。分析器应先检查学生路径中每一步是否由前一步与题目条件合法推出。只有路径本身失效时才标错，不因为顺序、记号或方法不同而扣错。

## 状态与记忆

- L1：目标、偏好、学习证据和已确认的误区；
- 工作区：题目原文、attempt、候选错因账本、练习和报告；
- L2：用户授权归档的知识材料；
- L3：会话连续性。

状态机不替代平台的知识估计。工作区的 `observation/suspected/...` 描述的是某个可验证错因假设，不是虚构的掌握率。

## 第一版边界

课程参考文件提供稳定路由和典型前置关系，不宣称覆盖所有地区教材。遇到超出参考范围但仍属于中小学数学的问题，可以创建临时概念描述用于当次分析，但不得静默写入永久课程表。
