# 模块化渐进学习

适合初次接触一个领域、经常追问和跳转话题、希望把同一概念用于不同问题的学习者。先提供小范围的领域概览，再围绕当前问题学习一个可迁移的概念；学习者可以选择深入、应用、拓展或暂停。

## 与情景化讲题的区别

本模板主要组织学习顺序、问题分支和跨轮次衔接。情境作为可选的应用或迁移练习，在学习者请求、偏好证据或教学需要支持时引入。基础概念仍需说明其定义、产生原因、用途与边界，避免把一个例子当成概念的全部意义。

## 安装与运行

发布到配置的 Hub 后，可从 Inno Agent 简单模式选择“模块化渐进学习”。客户端会把 `agent.md` 和 `.skills/` 复制到新工作区。

本地预览时，将本目录的 `agent.md` 和完整 `.skills/` 复制到一个新工作区，然后新建并绑定会话。复制时需要包括以点开头的隐藏目录；只上传 `SKILL.md` 会漏掉参考文件。预设已经带有私有 Skill，无需再安装同名的全局 Skill。

`agent.md` 提供工作区原则，`.skills/modular-learning-orchestrator/SKILL.md` 提供具体教学流程，`references/` 提供记忆边界、分支与验收要求。本模板不需要新增服务器代码，也不依赖学习者个人连线功能。

## 记忆与工具

| 用途 | Inno Agent 提供的工具 | 边界 |
|---|---|---|
| 判断目标、偏好与知识状态 | `get_learner_context` | 以已有证据和学习者确认的信息为准 |
| 查询概念、资料与联系 | `l2_query` | 空结果不作为事实依据 |
| 恢复之前的问题和分支 | `l3_recall` | 仅在恢复历史时使用，不编造断点 |
| 保存明确目标、偏好及学习表现 | `record_learning_event`、`record_learning_evidence` | 助手讲解本身不证明学习者已掌握 |
| 保存有依据的学习资料 | `l2_archive` | 依据实际结果报告归档情况，不保证每轮更新图谱 |

工具未启用、记忆为空或查询失败时，使用当前对话继续教学，并说明相关限制。短回复和沉默不应被直接解释成固定性格或动力下降。微信与飞书的短回合规则只在渠道已接通时适用；此模板本身不接通渠道，也不自动开启主动消息。

## 手动体验

在新会话按顺序发送以下自然问题，不需要在问题中指定工具名或教学格式：

1. “我想学博弈论，但完全没接触过，不知道从哪里开始。”
2. “等一下，你说的策略和我平时说的计划有什么区别？”
3. “先别用故事，我想先弄清楚这个概念。”
4. “除了商业竞争，这个概念还能用在哪儿？”
5. “今天先到这里，下一次我想继续刚才没讲完的问题。”

继续同一会话时，可发送“我们上次停在哪里了？”。跨会话恢复还取决于 L3 是否已记录并可检索到相关历史，找不到时应如实说明。

观察：是否先给出简短概览；追问能否打断原路线；拒绝情境后是否继续解释概念；能否说明多个用途及边界；恢复时是否忠于可检索历史。普通问题不应反复出现内部编号、“积木”或整套固定问卷。

## 验证范围

这是依赖模型遵循指令的内容模板，并非确定性教学状态机。以上为手动验收步骤，不代表学习效果已经得到对照实验验证；本次 Hub 打包只核对结构、元数据、引用和工具名称。对比测试应保持模型、学习资料和初始画像一致，分别使用普通工作区与本模板，并查看工具调用记录和实际学习者表现。
